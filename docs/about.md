# Guardian: назначение и задачи проекта

Guardian контролирует исходящие HTTP-запросы приложений и открывает CONNECT-туннели для HTTPS. Клиенты направляют трафик через прокси, а администратор задаёт правила доступа через REST API. Сервис написан на Go с использованием `fasthttp`.

## Задача

Приложения обращаются к внешним API, облачным сервисам и партнёрским системам. Когда ограничения на такие обращения задаются отдельно в каждом приложении, их трудно обновлять и проверять. Guardian переносит правила на общий прокси: администратор может запретить запрос по атрибутам, ограничить частоту обращений пользователя и получить сведения об обработанном трафике.

Сервис рассчитан на развёртывание в собственной инфраструктуре. Правила и пользователи хранятся в PostgreSQL, Redis используется для кэширования и общих счётчиков RPS, Prometheus собирает метрики. События можно публиковать в Kafka.

## Цель разработки

Реализовать исходящий HTTP-прокси с управлением правилами через API, разграничением доступа по ролям и ограничением нагрузки по IP и пользователю. Для HTTPS предусмотрены CONNECT-туннели без расшифровки TLS.

Проект включает следующие задачи:

1. Реализовать пересылку HTTP-запросов и открытие CONNECT-туннелей, настроить пулы соединений, DNS-кэш и таймауты.
2. Добавить правила `allow`, `block` и `modify` с деревом условий `AND`/`OR`/`NOT`, приоритетами и обновлением без перезапуска процесса.
3. Реализовать проверку локальных JWT HS256 и альтернативный режим проверки токенов внешнего IdP через JWKS или introspection.
4. Разграничить доступ к Admin API и прокси по ролям, применять квоту `quota_rps` из токена.
5. Проверять адреса назначения и учитывать заголовки IP клиента только от доверенных балансировщиков.
6. Предоставить API правил, пользователей, тестирования условий и статистики; описать его в OpenAPI.
7. Добавить метрики, проверки состояния, аудит административных действий и журналы запросов.
8. Подготовить конфигурацию, примеры Docker Compose, Kubernetes и HAProxy, проверить поведение модульными и нагрузочными тестами.

## Область применения

Guardian можно использовать как общий прокси для приложений, которым нужен контролируемый доступ к внешним HTTP-сервисам. Для этого клиенты должны направлять запросы через Guardian; предотвращение обхода прокси требует настройки сети.

HTTP-правила проверяют метод, URL, IP клиента, заголовки, тело и данные пользователя. Для HTTPS доступны атрибуты запроса CONNECT и адрес назначения. Пути URL, заголовки и тела запросов внутри TLS-туннеля прокси не видит; `modify` к ним не применяется.

Проверка частных и локальных адресов снижает риск SSRF. DNS-проверка и подключение выполняются раздельно, поэтому защита от DNS rebinding остаётся ограничением реализации. Ограничения реализации проверки и отзыва токенов, кэширования и масштабирования описаны в [architecture.md](./architecture.md).

Пропускная способность зависит от конфигурации, ресурсов, задержки целевых серверов и профиля нагрузки. Доступные результаты и недостающие условия измерений приведены в [test-result.md](./test-result.md).

## Термины

| Термин | Значение |
|--------|----------|
| Admin API | REST API управления Guardian; по умолчанию слушает `:8081`. |
| Forward-прокси | Посредник, которому клиент передаёт запросы к целевым серверам. |
| Upstream | Целевой сервер, к которому Guardian пересылает запрос или открывает туннель. |
| CONNECT | Метод HTTP для открытия TCP-туннеля через прокси. |
| TLS | Протокол защиты соединения; используется в HTTPS. |
| Filter Engine | Компонент, который сопоставляет запрос с правилами и выбирает действие. |
| `allow` / `block` / `modify` | Действия правила: разрешить запрос, вернуть отказ, изменить HTTP-запрос или ответ. |
| RBAC | Разграничение доступа по ролям: `admin`, `moderator`, `user`, `guest`. |
| JWT | Подписанный токен с данными пользователя и сроком действия. |
| Claims | Поля токена: например, `user_id`, `role`, `active`, `quota_rps`. |
| HS256 | Подпись JWT с общим секретом, используемая в локальном режиме Guardian. |
| IdP | Внешний поставщик удостоверений и токенов. |
| OAuth2 | Протокол делегированной авторизации. Guardian проверяет токены, но не реализует выдачу OAuth2-токенов. |
| JWKS | Набор ключей IdP для проверки подписи JWT. Guardian поддерживает RSA. |
| Introspection | Запрос к IdP о статусе и атрибутах токена. |
| Bootstrap | Выдача локального JWT существующему активному пользователю по отдельному секрету; предназначена для разработки и начальной настройки. |
| RPS | Число запросов в секунду. |
| `quota_rps` | Пользовательская квота из токена. Значение ≤ 0 означает `rate_limit.default_rps`. Для CONNECT учитывается создание туннеля. |
| Token bucket | Алгоритм ограничения частоты с допустимым кратковременным всплеском нагрузки; используется при локальном ограничении RPS. |
| SSRF | Инициирование злоумышленником запросов от имени сервера к выбранным адресам, в том числе внутренним. |
| CIDR | Запись IP-подсети, например `10.0.0.0/8`. |
| Trusted proxies | IP/CIDR балансировщиков, от которых разрешено учитывать X-Forwarded-For и X-Real-IP. |
| Read replica | Реплика PostgreSQL для чтения; данные могут отставать от основной БД. |
| TTL | Время хранения записи в кэше. |
| C4 | Модель описания архитектуры на уровнях контекста, контейнеров, компонентов и кода. |
